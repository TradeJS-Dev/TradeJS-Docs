---
title: MCP для Codex и Claude Code
description: Подключение ИИ-ассистента к своему приложению TradeJS через OAuth.
---

TradeJS предоставляет MCP через Streamable HTTP по адресу `/mcp`. Codex и Claude
Code могут читать рынок, графики, текущие стратегии, сигналы, сохранённые ордера
и результаты бэктестов, а также запускать ограниченные фоновые проверки.
Общение с ИИ происходит в выбранном клиенте. MCP заменяет прежний AI-дровер
дашборда. Runtime AI/ML-фильтры и сценарии Telegram сохраняют свои задачи.

## Подготовка

Нужен согласованный выпуск пакетов TradeJS с MCP-маршрутами приложения и командой
`tradejs mcp-worker`. В прежних опубликованных версиях этих функций нет.
Укажите `MCP_PUBLIC_URL=https://YOUR_APP_HOST/mcp` или тот же публичный адрес в
`APP_URL`. HTTPS обязателен, кроме локальной разработки.
`MCP_ENABLED=false` отключает новые MCP/OAuth-запросы. OAuth-разрешения, отзыв
доступа, состояния задач и аудит хранятся в Redis; используйте постоянное хранилище.

Откройте **MCP** в боковом меню приложения. Там указаны адрес сервера и активные
подключения. Браузерная сессия определяет пользователя TradeJS. Перед согласием
проверьте имя клиента, адрес возврата и права. Используется OAuth Authorization
Code с S256 PKCE и динамической регистрацией публичных клиентов.
Access token действует 15 минут; refresh token меняется при обновлении,
разрешение действует до 30 дней. Отзыв подключения блокирует его токены при
следующих запросах. Вход и согласие выполняет человек; агент не авторизует себя.

## Подключение Codex

Выполните сами, заменив адрес:

```bash
codex mcp add tradejs --url https://YOUR_APP_HOST/mcp
codex mcp login tradejs --scopes market:read,runtime:read,backtests:read,backtests:run,diagnostics:read,diagnostics:run
```

Codex CLI и приложение Codex могут использовать один настроенный удалённый
сервер. Если инструменты не появились, обновите подключение или перезапустите
клиент. Отдельный API-ключ не нужен.

## Подключение Claude Code

```bash
claude mcp add --transport http tradejs https://YOUR_APP_HOST/mcp
```

В Claude Code откройте `/mcp`, выберите TradeJS и пройдите авторизацию в браузере.
Нужен актуальный клиент с поддержкой Streamable HTTP, OAuth discovery,
публичной регистрации и S256 PKCE. Согласие в браузере всегда даёт пользователь.

## Права и инструменты

| Право | Операции |
| --- | --- |
| `market:read` | Список монет, текущие цены, закрытые свечи и индикаторы |
| `runtime:read` | Доступные развёртывания, настройки стратегий, сохранённые сигналы, решения, ордера и счётчики пропуска |
| `backtests:read` | Конфигурации, результаты и состояния задач |
| `backtests:run` | Запуск и отмена бэктестов своего клиента, чтение состояния |
| `diagnostics:read` | Проверенные отчёты, загрузка артефактов частями и состояния задач |
| `diagnostics:run` | Сбор evidence, изолированный feedback replay/parity и отмена задач своего клиента |

На странице согласия выберите нужные права. Запуск задач изначально не отмечен,
даже если клиент запрашивает все права. Если клиент не указал scope, страница
предлагает поддерживаемые права для вашего явного выбора.

Инструменты появляются согласно выданным правам. Для доступа к развёртыванию
нужен торговый счёт, принадлежащий пользователю. MCP не предоставляет размещение,
отмену или закрытие реальных ордеров, запись runtime-конфигурации, деплой или
отправку уведомлений.

Сначала вызовите `tradejs_info`, чтобы проверить адрес, пользователя и worker.
Для production-запросов затем вызовите `runtime_get_status`. Всегда указывайте
развёртывание и период `[startTime,endTime)`. Отсутствие сохранённых записей не
доказывает отсутствие работы. Runtime-списки ограничены семью днями. Продолжайте
чтение после пустых страниц до курсора `0`; курсор действует десять минут и
привязан к фильтрам. Счётчики пропуска служат диагностике и не заменяют
неизменяемые evidence с точным составом пакетов и конфигурацией.

Кнопка **Copy context for AI** на дашборде копирует источник рынка, universe, монету,
интервал, выбранный бэктест и ссылку на страницу. Вставьте контекст в клиент и
укажите период анализа. Видимая область графика не копируется. Сохранённые
фигуры стратегии доступны через `runtime_get_signal`: передайте signalId,
развёртывание, timestamp и strategy из списка сигналов.

## Фоновые задачи

Запускайте `yarn mcp:worker` из Project после создания
`runtime-package-manifest.json`. Состав пакетов worker должен точно совпадать с
приложением. Production Compose содержит отдельный worker и временный
`mcp-replay-redis` в необязательном профиле `mcp`. Включайте профиль в обычном
процессе выпуска после публикации совместимого образа. Укажите `MCP_WORKER_ENABLED=true` в принадлежащем Git файле Project
`deploy/runtime.env` этого выпуска. Деплой останавливает прежний worker, запускает
новый и проверяет совпадение состава пакетов. Откат восстанавливает worker
вместе с приложением. Прерванные задачи становятся failed без автоматического
повтора. По умолчанию флаг равен `false`. Worker не запускает торговый entrypoint
и не требует Docker socket.

`backtest_start` сохраняет снимок именованной Redis-конфигурации. Ограничения:
до 90 прошедших дней, 20 монет и восьми комбинаций, только кеш истории, один
процесс, без платных AI-запросов. Краткие результаты сохраняются даже в fast
режиме и доступны через постраничные инструменты бэктестов. `diagnostics_start` собирает runtime evidence
за период до семи дней либо запускает replay по проверенному evidence именно
этого развёртывания. Для replay необходим `MCP_REPLAY_REDIS_HOST` с отдельным
Redis, Timescale только для чтения, удалённые credentials, запрет ордеров и
совпадение исходных пакетов и образа. Существующие проверки отвергают
несовместимые evidence.

Запуск сразу возвращает job id. Сохраняйте его, читайте `job_get` и повторно
используйте `idempotencyKey` только для идентичного запроса. Отключение клиента
не отменяет задачу. Для отмены нужен явный `job_cancel`. После перезапуска worker
прерванные задачи становятся failed и автоматически не повторяются. Лимиты:
одна активная задача, час на выполнение и десять запусков на пользователя в час.
Состояние задачи хранится семь дней; срок хранения файлов определяет Project.

## Отчёты без SSH

Сначала используйте `diagnostics_list_reports`. Каталог ищет завершённые
runtime-evidence и runtime-feedback в `data/runtime-evidence`,
`data/runtime-feedback` и каталоге пользователя в `data/mcp`. Проверяются
владелец, доступ к развёртыванию, маркер завершения, размер и SHA-256.
Повреждённые, незавершённые и недоступные пакеты исключаются. Размер каждого
файла данных и лога в каталоге ограничен 64 МиБ; более крупные пакеты
анализируйте отдельным локальным CLI-процессом. Каталог ограничен
по размеру поиска и сообщает об усечении. Отсутствие пакета не доказывает,
что production ничего не запускал.

`diagnostics_get_report` возвращает отчёт или краткое содержание. `artifact_get`
отдаёт base64-части с offset, общим размером и SHA-256. Соедините декодированные
байты, проверьте размер и хеш и анализируйте локально нужным skill. Проверьте
также происхождение и полноту evidence. Calibration, scorecard, формальное
исследование стратегий и деплой используют отдельные CLI-процессы. MCP не
принимает произвольные команды и пути. Нельзя автоматически переходить к SSH,
если не хватает прав или артефакта.

## Skills и диагностика подключения

Исходники skills находятся в `investing/.codex/skills`; `$tradejs-mcp` описывает
работу клиента. Установленные Projects обновляются через `create-tradejs
--update-skills` с последующими проверками. Обновление отказывается перезаписывать
изменённые управляемые файлы: сначала согласуйте локальные изменения.
Оба клиента должны соблюдать Project `AGENTS.md`. Файл `CLAUDE.md` подключает
его и указывает Claude Code на те же исходники `.codex/skills` без копирования.

Ответ `401` содержит адрес OAuth discovery. После отзыва или истечения доступа
войдите заново самостоятельно. `403` для браузерного origin означает отличие
адреса запроса от публичного адреса в настройках. Если worker недоступен,
задача не ставится в очередь. Перед production проверьте на тестовом пользователе
с кешированной историей согласие, обновление токена, отзыв и изоляцию данных
в обеих установленных программах.
