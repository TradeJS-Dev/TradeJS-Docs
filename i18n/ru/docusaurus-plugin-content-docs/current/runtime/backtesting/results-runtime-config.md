---
title: Как использовать проверенную конфигурацию в реальной торговле
---

Переход от хорошего бэктеста к реальной торговле — контролируемое изменение, а
не автоматический экспорт результата. В рабочую среду должна попасть точная
версия стратегии, полная конфигурация и ограничения риска, которые прошли
проверку.

## Просмотр сохранённых результатов

Команда `results` собирает сводку бэктестов и показывает покрытие инструментов
для одной стратегии:

```bash
npx @tradejs/cli results \
  --strategy <StrategyName> \
  --coverage \
  --user root
```

Команда также умеет вести локальный список лучшего результата по каждому
инструменту:

- `--merge` заменяет запись, только если новая сохранённая прибыль выше;
- `--update` полностью заменяет список;
- `--clear` удаляет локальный список.

Эти режимы помогают организовать результаты исследования. Они не меняют
настройки реальной торговли, не включают стратегию и не разрешают размещение
ордеров. Сейчас знаменатель для `--coverage` берётся из набора инструментов
Bybit.

## Проверка кандидата

Перед использованием конфигурации на текущем рынке проверьте:

1. **Данные:** нет необъяснимых пропусков, дублей, сдвигов времени и утечки
   будущей информации.
2. **Исполнение:** комиссии, проскальзывание, правила исполнения, задержки,
   funding и ограничения заимствования соответствуют площадке и обороту.
3. **Независимая выборка:** результат приемлем на данных, которые не
   использовались для подбора параметров.
4. **Устойчивость:** небольшие изменения параметров и издержек не разрушают
   результат.
5. **Риск:** просадка, экспозиция, концентрация и убыток на сделку подходят для
   выбранного счёта.
6. **Ёмкость:** размер ордеров соответствует наблюдаемой ликвидности.

Сохраните полный отчёт и обоснование выбора. Список лучших настроек по отдельным
инструментам сам по себе не является портфельной или рабочей конфигурацией.

## Обновление рабочей конфигурации

Настройки реальной торговли объявляются в `tradejs.config.ts`:

1. Скопируйте полную проверенную конфигурацию в нужное развёртывание.
2. Зафиксируйте точную версию пакета стратегии, использованную при проверке.
3. Проверьте набор инструментов, торговый счёт, риск и поле `enabled`.
4. Сохраните конфигурацию и lock-файл одним коммитом, чтобы изменение можно
   было проверить и откатить.
5. Запустите проверки проекта и проверьте итоговую настройку. Строгий parser
   отклоняет неизвестные config fields, а runtime вычисляет `strategyRevision`
   и `deploymentCompositionId`; числовое поле version вести не нужно.

```bash
npx @tradejs/cli runtime-control verify \
  --user root \
  --deployment <deployment>
```

Страница стратегий показывает эту конфигурацию, но не переписывает её. Команды
паузы и возобновления временно запрещают новые входы, не меняя параметры.

## Проверка перед размещением ордеров

Сначала воспроизведите точное развёртывание на истории, затем выполните один
расчёт на текущем рынке без `--makeOrders`:

```bash
npx @tradejs/cli replay \
  --user root \
  --deployment <deployment> \
  --days 7 \
  --cacheOnly

npx @tradejs/cli signals \
  --user root \
  --deployment <deployment> \
  --cacheOnly
```

Разрешайте размещение ордеров только после проверки воспроизведения, свежести
данных, прав счёта, риск-контролей, мониторинга и процедуры остановки. Начальный
лимит риска должен быть небольшим, а условия остановки — определены заранее.
