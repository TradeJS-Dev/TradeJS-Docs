---
title: Сетка параметров бэктеста
---

Для [первого бэктеста](./first-backtest) настройки MaStrategy уже заполнены.
Чтобы проверить другие значения или выбрать другую стратегию, сохраните
настройки в своём проекте. В примере ниже проверим два периода быстрой
скользящей средней.

## Формат сетки

Сетка перечисляет значения для проверки. Укажите массив, даже если нужно
одно значение. Для полей, которых нет в сетке, TradeJS возьмёт настройки
стратегии по умолчанию.

```json
{
  "INTERVAL": ["15"],
  "MA_FAST": [21, 34],
  "MA_SLOW": [55]
}
```

TradeJS выполнит два теста. В первом период быстрой средней равен 21,
во втором — 34. Период медленной средней в обоих случаях равен 55.
Если бы для обеих средних было по два значения, получилось бы четыре теста.

## Ручное сохранение сетки

Из папки проекта сохраните настройки в локальном Redis. Docker и сервисы
TradeJS должны быть запущены. Чтобы сохранить старые настройки, задайте новое имя.

```bash
docker compose -f docker-compose.dev.yml exec -T redis redis-cli SET \
  'users:root:backtests:configs:MaStrategy:compare' \
  '{"INTERVAL":["15"],"MA_FAST":[21,34],"MA_SLOW":[55]}' NX
```

Ответ `OK` означает, что настройки сохранены. Пустой ответ означает, что это
имя уже занято. `MaStrategy` выбирает стратегию, а `compare` — имя настроек.

В приложении откройте раздел **Backtest**, выберите **MaStrategy** и
**MaStrategy:compare**, затем укажите рынок и период. Если удобнее работать
в терминале, выполните команду проекта:

```bash
npm run backtest -- --user root --config MaStrategy:compare \
  --connector binance --tickers BTCUSDT --timeframe 15 --days 30 --tests 2 --parallel 1
```

## Параметры для отдельных направлений

У некоторых стратегий можно задать отдельные значения для покупок и продаж.
Например, `TARGET_R_MULT_SHORT` может отдельно менять цель короткой позиции.
Какие поля поддерживают окончания `_LONG` и `_SHORT`, указано на странице стратегии.

## Воспроизведение рабочей конфигурации

Запишите каждую рабочую настройку стратегии как массив с одним значением.
Используйте ту же версию пакета, интервал, инструменты и период. Цену,
комиссию, проскальзывание и задержку задавайте в самом бэктесте. Поля
`ENV` и `MAKE_ORDERS` в сетку добавлять не нужно. Сохранённые настройки
влияют только на бэктесты.

## Частые ошибки

### `Backtest config "<name>" not found`

Сверьте имя пользователя и часть после `backtests:configs:` в ключе Redis.
В примере это `root` и `MaStrategy:compare`.

### `must include strategyName and strategyConfig grid`

Сохраните объект JSON. В каждом поле должен быть массив хотя бы с одним значением.

### Запускается другая стратегия

Часть имени до первого двоеточия выбирает стратегию.
